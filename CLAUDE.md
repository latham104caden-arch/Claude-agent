# Revised Research storefront: working rules

- This is Caden Latham's project, deployed on **his own** Vercel account. It is separate from Ventra Sciences. Never push to or deploy under the Ventra repo or Kaseton's Vercel team.
- Stack: Next.js 15 App Router, React 19, TypeScript, plain CSS. Don't add Tailwind or a UI kit without asking.
- Colors come only from `styles/tokens.css`. No hard-coded hex values in components.
- Products are read only through `lib/catalog.ts`. `data/products.ts` is placeholder data.
- **Email marketing: Omnisend only** (owner-approved 2026-10-02): web tracking snippet in `components/chrome/Omnisend.tsx`, newsletter → Omnisend contacts in `app/api/newsletter/route.ts` (needs `OMNISEND_API_KEY`). **Transactional email: Resend** (owner-approved 2026-10-02) for account sign-in codes, (2026-10-03) order confirmations, and (2026-10-09) Research Partner pricing requests to the team's support inbox, from orders@revisedresearch.com with replies to support@ (`lib/email.ts`). **Web push "drop alerts"** (owner-approved 2026-10-05): browser-native push, no third-party provider; subscriptions in Vercel Blob (`lib/push.ts`), sent only via the owner-only `/api/push/send`; they unlock the RR25 first-order code (`components/offer/FirstOrderOffer.tsx`, enforced in `lib/discounts.ts`). **SMS marketing via Omnisend** (owner-approved 2026-10-05): opt-in only, from an unticked box with the TCPA disclosure (account sign-up, `components/account/SignIn.tsx`); never auto-subscribe phone numbers. **Do not connect any other messaging provider** until the owner approves it. The other form API routes are intentional 501 stubs (`lib/api/stub.ts`).
- Research Partner Program (`/partner`, `lib/partner.ts`): 10/20/30+ of the same vial (SKU) at 40/45/50% off that vial, shown in dollars and percent; different vials don't combine. Never auto-applied at checkout: labs send their kit from the page and the team sets up the pricing. Each request is saved privately in Blob (`partner-requests/`, listed in /admin), pushed to team devices, and emailed to support@ and every `ADMIN_EMAILS` address (from orders@, falling back to the sign-in sender if Resend refuses orders@); /admin shows each request's email status. The team approves a request in /admin, which creates a private single-use link (`/partner/checkout/<token>`, 14 days, `lib/partner-approvals.ts`) for exactly that kit at partner prices; the link is emailed to the lab via Resend (owner-approved 2026-10-09) and can be copied from /admin. Regular checkout never applies partner pricing.
- Team dashboard: `/admin` (team emails in `ADMIN_EMAILS`, emailed-code sign-in). Numbers come straight from Stripe (`lib/metrics.ts`), summed in cents, with an accuracy check against card charges. Never show invented or estimated figures. New-order alerts are browser push to team devices only (`lib/alerts.ts`, Blob `team-push/`), sent from the Stripe webhook once per order.
- Shopper funnel (visits, product views, add to cart, checkout started) is counted first-party in Upstash Redis (`lib/funnel.ts`, `/api/track`, random session IDs, no personal data); purchases always come from Stripe. The same steps go to Omnisend as its standard events (`lib/track-client.ts`) for abandonment automations, plus "started checkout" from expired Stripe checkouts for shoppers who left the email box ticked.
- Marketing email/SMS copy: use the `email-writer` agent (`.claude/agents/email-writer.md`). It drafts in Omnisend and never sends.
- Never commit `.env*`, `.vercel/`, or keys. Stage explicit paths. Never use `git add -A`, because iCloud "name 2" duplicates can sneak in.
- Before pushing: `npm run check && npm run build`.
- RUO: every customer-facing surface is "research use only". `lib/ruo.ts` and `scripts/check-ruo.mjs` block the names in `data/ruo-banned.json`. Never weaken either one.
- Reviews: publish only real, verified reviews. Never seed invented quotes.
- Legal pages are drafts until counsel-reviewed text replaces them.
